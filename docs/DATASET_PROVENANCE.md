# Dataset provenance

Every external resource has to be bound to a source digest before it enters a baseline. That rule was already written into the pairwise and readout work, and it was already being kept for models, tools and search indices — but not for the data. Of the fifteen dataset directories staged under `data/` when this record was started, exactly one carried a manifest, so fourteen of them, including the ProteinGym panel behind the mutation-ranking axis and the UniRef50 corpus behind every retrieval control, were being used with no recorded digest, release or retrieval route at all.

`data/dataset_registry.json` closes that. It declares every dataset directory, records the provenance of each and carries a SHA-256 for every staged file. It now covers **21 directories, 47,545 files and 89.353 GB**: the original fifteen, the three endpoints described below, and three that arrived from concurrent campaigns while it was being built. It lives beside the data rather than in Git because `data/` is ignored, which is the same arrangement `data/megascale_tsuboyama2023/manifest.json` already used; that manifest is not replaced, and it remains the richer record for its own directory because it additionally binds each file to its upstream release digest.

## What the registry records

Each dataset carries two halves that fail in different ways, so they are produced differently.

The provenance half is authored: what the source is, where it came from, which release, when it was retrieved, under what command, under what licence and with what redistribution constraint. A field that cannot be recovered is written as `{"recoverable": false, "reason": ...}` and the reason is required, because a fabricated release string is worse than an admitted gap — it reads as provenance while binding nothing. The schema enforces the choice: a field that is neither a non-empty value nor a reasoned marker is refused.

The inventory half is measured. `scripts/transfer/build_dataset_registry.py` walks each declared directory and records a size and digest per file; it writes no provenance value and cannot invent one. It also refuses a data root whose directories and the registry's declarations disagree in either direction, which is the one path by which a dataset could otherwise appear and be used without provenance.

## Building and checking it

```bash
python scripts/transfer/build_dataset_registry.py            # measure anything not yet measured
python scripts/transfer/build_dataset_registry.py --remeasure ALL
python scripts/transfer/verify_dataset_registry.py           # re-read every file and refuse a mismatch
```

The first pass measured 47,519 files and 86.634 GB in 1,005 s of wall clock at 24 hashing threads, between 0.05 and 0.29 GB/s per dataset, on a host under heavy concurrent load; a full re-verification of the same tree took 679.6 s over 82.852 GB. That is a one-off cost, and the builder leaves an already measured dataset alone unless it is named in `--remeasure`, so authoring provenance afterwards does not force a re-read — which is also how the six directories added after the first pass were measured for 2.7 GB rather than 89.

Provenance did not come out complete, and the registry says where. Of the 21 datasets, the retrieval command is unrecoverable for 12, the retrieval date for 9, the release for 7, the source URL for 3 and the licence for 4, each with its own reason recorded. One is marked volatile.

The verifier is the operational gate and rehashes everything. `tests/test_dataset_registry.py` is the cheap continuous check: it verifies the registry's internal arithmetic and provenance schema, confirms every listed file exists at its recorded size, rehashes a bounded sample of them, and exercises the refusals — an altered file whose size is unchanged, a resized file, a listed file that is gone, a file on disk the registry does not list, an unrecoverable marker with no reason, and an inventory whose totals disagree with its own file list.

One dataset is excluded from digest verification and says why. `data/pairwise_assets` is concurrently owned by the pairwise-baseline deepening campaign, which began staging a UniRef90 release into it during the measurement: the file was 6.4 GB when hashed and 11.1 GB minutes later. Its digests are a snapshot of a partial download rather than a binding, so the entry carries a `volatile` marker with that reason and will need remeasuring once that campaign reports the release complete. Marking it is the point — an in-flight directory that silently failed verification, or silently passed it, would be worse than one that is declared unbindable.

## What could and could not be recovered

Six datasets carry a release that is recoverable from the staged bytes themselves, which is the strongest form available when no download record was kept: the Gene Ontology graph declares `releases/2026-01-23` and the annotation table `date-generated: 2025-12-04` against `releases/2025-11-30`; InterPro declares 108.0 with 51,489 entries dated 29-JAN-26; ExPASy ENZYME declares a release of 28-Jan-2026; the AlphaFold models carry `model_v6` in all 47,172 filenames; Pika-DS declares version 1.0.0 beside a pinned repository revision; and MegaScale is pinned to a dataset commit. The three newly staged endpoints carry a DOI or a download URL with the upstream checksum the host published.

The rest is a genuine gap and is recorded as one. Neither Swiss-Prot nor UniRef50 carries a release marker in the staged files and no download record survives, so both releases are unrecoverable; what is recorded instead is a measured content fingerprint — 574,627 Swiss-Prot entries, and 60,315,044 UniRef50 records over 17,277,105,157 residues — which identifies one release without naming it. ProteinGym is the same shape: 217 assay CSVs and a uniform upstream member timestamp of 2024-01-17 bound the archive without establishing a version string, and none is asserted. Retrieval dates and commands are unrecoverable for nine of the twelve pre-existing datasets; where a filesystem mtime is the only observation it is recorded as an observation about the files and not as a retrieval date.

Two datasets have no licence this project can establish, which is a redistribution constraint rather than a curiosity. The three curated variant-mechanism tables under `data/mechanism` carry only an author-year token in their filenames and no DOI, so the articles whose supplementary-material terms govern them have not been identified; the BioLiP table under `data/pdb` was staged without its terms. Both are recorded as unrecoverable and neither may be redistributed until identified. [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) carries the attribution consequences.

One recorded statement elsewhere does not describe this host, and the correction belongs here because it is a measured fact about a staged file. `docs/D1_PAIRWISE_BASELINE_READINESS.md` states that the UniRef50 source FASTA is not retained and only its DIAMOND index is. `data/uniref50/uniref50.fasta` is the complete source corpus, 24,637,540,125 bytes over 60,315,044 records and 17,277,105,157 residues, matching the record and letter counts of the index. That is a documentation inaccuracy and nothing more: the coupling-depth ceiling that record reports does not rest on which representation is on disk, because UniRef50 clusters at 50% identity and searching the FASTA returns the same clusters as searching its index. The ceiling is a property of the database's construction.

## The three endpoints staged for the capability map

Three datasets were acquired to lift named measurement limitations, and each one's support is counted rather than assumed. That order matters: the retrieval gate's saturation was found by counting units, and a variant count would have hidden it. `scripts/transfer/census_endpoint_support.py` produces these counts and `scripts/transfer/measure_endpoint_remoteness.py` the identity bands.

**Remote-homology targets: the Cho MGnify domain stabilities.** The retrieval and memorization gate cannot test its remote-identity end because both cohorts are saturated with near-duplicates — 49 of 64 stability groups and 140 of 163 ranking clusters sit at or above 95% identity to a retrieved homolog, and its three remote stability bands hold 1, 2 and 12 groups against a declared eight-unit percentile-interval floor. Deeper homolog corpora cannot fix that, and neither can more de novo designs: designs cluster by topology, so a design corpus adds variants rather than units, which is why Tsuboyama's own 148 design-labelled backgrounds collapse into one group under the frozen contract. Metagenome-assembled domains are a different kind of candidate, because UniProt-derived UniRef50 need not contain them.

The staged table holds 2,287,291 rows over 2,285,292 distinct names across three libraries — 813,652 in dmsv4, 573,641 in dmsv5 and 899,998 in dmsv7 — with 1,881,441 rows MGnify-flagged, 104,360 design-flagged and 301,490 neither. Each row carries deltaG in kcal/mol with 95% confidence intervals on the trypsin channel, the chymotrypsin channel and the combined estimate, and 1,968,501 of the 2,287,291 rows, 86.1%, have a combined interval no wider than 0.5 kcal/mol, which is the admission width the existing stability cohort applies. The mutational support is narrower than the row count suggests. Backgrounds are derived from the observed name set rather than a token grammar, because the file uses 31,412 distinct variant tokens; that gives 1,593,062 backgrounds, of which 123,770 carry at least one distinctly named variant, over 808,173 distinct variants — 510,458 single substitutions, 149,807 insertions, 145,750 deletions and 2,174 other, the last including scramble controls. Restricting to MGnify-flagged backgrounds that carry both their own wild-type row and at least one variant leaves **6,051 backgrounds** of 60 to 80 residues, median 68, with a median of one distinctly named variant each and at most 75. None of those 6,051 wild types matches a Tsuboyama 2023 background by exact sequence or by containment in either direction. The whole table is not disjoint from it — the non-MGnify part carries PDB-derived and design-labelled backgrounds that do match, including the MegaScale designs — so any use has to be restricted to the MGnify-flagged support rather than taken file-wide.

This dataset **cannot serve the plan's final external confirmation**, and the registry entry says so in place: it shares the cDNA-display proteolysis assay technology and an author with Tsuboyama 2023, which is one of the two sources that confirmation must avoid.

Whether it reaches the band it was acquired for is a measurement, and it does. 320 of the 6,051 backgrounds, drawn at seed 20260924, were searched against the retained 60,315,044-cluster UniRef50 index with the same settings and the same identity definition the retrieval gate uses — DIAMOND blastp `--very-sensitive --masking 0` at an e-value of 1e-3, and identity as the percent of the query identically matched by its best hit. Under the frozen band edges the 320 split **40 / 146 / 100 / 34** across `<30`, `30–70`, `70–95` and `≥95`, with all 40 in the lowest band returning no reported hit at all. **186 of 320**, a Wilson 95% interval of **[52.7%, 63.4%]**, are in the two remote bands, against 3 of 64 groups on the stability cohort and 5 of 163 clusters on the readout anchor. Grouping the same 320 under the frozen contract's own floors gives **192 groups, 174 of them singletons, of which 105 have every member remote** — against the declared eight-unit percentile-interval floor that the current remote bands, at 1, 2 and 12 groups, cannot clear.

The instrument was checked on the cohort whose answer is already known rather than trusted. All 478 MegaScale backgrounds were searched in the same pass, and splitting them on their own name pattern reproduces the structure the gate reports: the 239 whose names are a bare four-character PDB code split **2 / 3 / 77 / 157**, which is the near-duplicate saturation the gate records as 1 / 2 / 12 / 49 over its 64 selected natural groups, while the other 239 names split **132 / 16 / 32 / 59** with 132 returning nothing, which is what a de novo design does. That second group is also the clearest statement of why designs are not the answer: 148 of them are designs, they are the most remote sequences on the panel, and under the frozen contract they collapse into one group.

Two bounds travel with the number. It is a property of a 320-background sample, so the remote *proportion* extrapolates to the 6,051-background pool at roughly 3,500 backgrounds while the group count does not, because groups do not scale linearly with a sample; grouping the full pool was not run. And a band is a property of a search against one UniRef50 snapshot: no detected alignment is not absence from any model's pretraining corpus, which is the same limit the gate already records.

**External confirmation: Domainome 1.0.** The confirmation endpoint must come from neither ProteinGym's panel nor Tsuboyama 2023, and the 64 shared assays that limitation L50 records are exactly what makes that a real constraint rather than a formality. Domainome measures abundance by protein-fragment complementation in yeast, a different technology from both, from a different laboratory.

The staged score table holds 602,882 rows over 522 domains and 434 UniProt accessions, 574,161 of them substitutions and 28,721 stop-codon rows, with a median of 1,161 variants per domain, and carries a per-variant standard error: over 536,686 variants the normalized-fitness sigma runs from 0.0027 to 3.1067 with quartiles 0.0575, 0.0880 and 0.1412 in normalized-fitness units. Each domain's wild type is reconstructed as the per-position consensus of its own rows, and that reconstruction is checked rather than trusted: **0 of 574,161** substitution rows differ from their domain's consensus at more than one position.

Verification against both development sources was done by target sequence and not only by identifier, and the two answers differ, which is the point of doing both. **No** ProteinGym assay identifier names Beltran or the domainome, in the staged 217 or in the v1.3 reference list. By sequence, **17 of 522** domains match a ProteinGym target and **17 of 522** match a Tsuboyama 2023 background, 6 of them in both, so **28 domains, 5.4%, overlap one of the development sources and an identifier check alone would have missed every one**. Matches run in both directions, because a domain and a full-length assay target can be the same protein at two extents: `P62993_PF00018_159` is contained in `GRB2_HUMAN_Faure_2021`, three PDZ domains of `P78352` in `DLG4_HUMAN_Faure_2021`, and `HHH-rd1-0142_rockdoms_1` is byte-identical to the MegaScale design `HHH_rd1_0142.pdb`. Dropping all 28 leaves a confirmation support of **494 domains over 413 UniProt accessions and 120 distinct Pfam accessions, 568,234 rows of which 541,202 are substitutions**. On the family count that is what matters: 120 candidate independent units against the eight-unit floor.

**A function endpoint: SKEMPI 2.0.** The molecular-recognition and function gate has no admitted instrument, and its admission condition is that the endpoint be a measurement rather than an annotation, which rules out the GO, InterPro and BioLiP tables already staged. SKEMPI holds 7,085 mutation rows over 348 complexes, 341 distinct PDB entries and 237 named partner pairs, drawn from 295 distinct publications. 6,798 rows carry a dissociation constant for both the wild type and the mutant, and 6,794 of those yield a binding free-energy change at the stated temperature, from −12.22 to +12.22 kcal/mol with a median of +0.771; 4,956 are single-point mutations. Of 344 complexes with a derivable value, 150 carry at least eight mutation entries.

Its weakness is stated rather than worked around: SKEMPI carries **no per-entry uncertainty column**, so the gate's own noise floor cannot be read off it. What the table does support is a repeated-measurement estimate — 5,914 distinct complex-and-mutation entries, of which **363 were measured by more than one publication**, disagreeing by a median of 0.237 kcal/mol with quartiles 0.086 and 0.540, a maximum of 5.365 and a root-mean-square of 0.669, and 45 of the 363 disagreeing by more than 1 kcal/mol. That is a **lower bound** on total uncertainty and not a calibrated uncertainty model: two publications reporting the same mutation share the underlying biology and often the assay principle, while their spread also absorbs literature-reporting heterogeneity that a single laboratory would not incur. A gate built on this endpoint inherits that bound. Establishing that a usable endpoint exists locally is all that is claimed here; no gate is built, and the dataset licenses a binding-energetics contrast on structurally resolved complexes and nothing about catalysis or specificity.

## Endpoint qualification

Provenance makes a dataset traceable; it does not make it usable. Each of the three endpoints is therefore qualified to the standard the admitted endpoints met, and the result is frozen in `data/endpoint_qualification_20260924.json`, SHA-256 `f36bd278d201fcc7b547e489d2f9d93372d0f4a42ba3f381182419808433d695`. That file carries the authored half — which column is the target, in what unit, under what sign convention, what one independent unit is, and what the endpoint licenses and does not — beside the measured quantities, which it copies from the two reports that produced them rather than restating.

Each floor is measured from the replicate or channel structure the source actually carries, and one of the three is uncomfortable enough to state first. **The MGnify stability endpoint's two protease channels disagree substantially.** On the 1,539,704 of 2,287,291 rows whose trypsin, chymotrypsin and combined intervals are all no wider than 0.5 kcal/mol, and restricting to the 1,413,334 MGnify-flagged among them, the trypsin-minus-chymotrypsin difference has a mean of **−0.478 kcal/mol** and a root-mean-square of **0.824 kcal/mol**, with the absolute difference at a median of 0.502, a 90th percentile of 1.342 and a maximum of 4.849; the two channels correlate at a Pearson coefficient of 0.857. Against a combined deltaG whose own standard deviation over the same rows is 1.251 kcal/mol, on a range of −1.291 to 7.355, the channel-disagreement floor is about two thirds of the endpoint's own spread, and the mean offset means the channels are not interchangeable: a contrast that differences one construct across channels carries that −0.478 kcal/mol bias. The endpoint is usable, and an effect below roughly 0.8 kcal/mol on a single construct is inside its floor.

**Domainome** reports a per-variant standard error and also permits an independent check of it. Over 536,686 variants the normalised-fitness sigma runs 0.0027 to 3.1067 with a median of 0.0880 and quartiles 0.0575 and 0.1412. Independently, 487,175 variants carry all three biological replicates with non-zero input and output counts, and the standard deviation of their log2 output-over-input enrichment has a median of 0.655 with a 90th percentile of 1.575 and a root-mean-square of 0.986 in log2 units, with replicates 1 and 2 correlating at 0.832. The two are in different units — one is the fitted error on a per-domain normalised scale, the other the raw enrichment spread — so the replicate figure is a check that the reported sigma has real replicate structure behind it and not a substitute for it. Independent units are 494 domains over 413 UniProt accessions and 120 Pfam accessions once the 28 overlapping domains are dropped.

**SKEMPI** has no per-entry uncertainty, so its floor comes from the repeated-measurement structure and nowhere else. Its endpoint spreads widely — 6,794 derivable values with a median of +0.771 kcal/mol, quartiles 0.035 and 2.125, and a standard deviation of 2.050 — and 363 of its 5,914 distinct complex-and-mutation entries were measured by more than one publication, disagreeing by a median of 0.228 kcal/mol, a 90th percentile of 1.094, a maximum of 5.366 and a root-mean-square of 0.668, with 45 of the 363 disagreeing by more than 1 kcal/mol. Its units are 348 complexes and 4,956 single-point mutations, not the 7,085 rows, and 150 complexes carry at least eight mutation entries. The floor is a **lower bound**: two publications reporting one mutation share the biology and often the assay principle, while their spread also absorbs literature-reporting heterogeneity a single laboratory would not incur. It is usable as a floor and not as a calibrated error model, and a gate built on this endpoint inherits that.

None of the three is used by a gate, and no gate is built on any of them here. A qualified endpoint that no gate has yet read is the right state for the later-stage function and external-confirmation gates to find them in.

## What the registry does not cover

Its scope is `data/`, at the instant it was measured. Three dataset directories appeared there from concurrent campaigns while this registry was being built, and each was declared as it appeared; a fourth arriving now would make the builder refuse the data root until it is declared, which is the behaviour rather than a fault. Three other locations hold external material and keep their own records: `external_resources/`, whose manifest lists the staged tools, model weights and Pfam release; the UniRef50 DIAMOND index outside the project tree, whose digest the pairwise readiness record and the retrieval gate both carry; and the 2026-08-12 offload on the second volume, which carries its own README and a `SHA256SUMS` over every file, as `data/RELOCATED.md` records.
